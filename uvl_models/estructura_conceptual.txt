Reglas semánticas del template
Hay varias decisiones que conviene dejar explícitas para que el builder no introduzca restricciones incorrectas:
Elemento	Regla
Card Types	Una o varias selecciones. Al menos una.
Supertypes	Cero o varios.
Subtypes	Solo disponibles si se selecciona su Card Type padre. Cero o varios.
Layout	Exactamente una alternativa.
Mana Cost	Puede no existir; si existe, sus componentes coexisten.
Mana components	Valores enteros independientes, incluyendo cero.
Colors	Conjunto de cero a cinco colores.
Color Identity	Conjunto independiente de cero a cinco colores.
Color Indicator	Propiedad opcional; si existe, uno o varios colores.
Power/Toughness	O no existe el grupo, o existen ambas propiedades. Cada una puede ser numérica o especial.

Algunas decisiones importantes
1. Type System

Los subtipos se generan dinámicamente a partir de la taxonomía, nunca mediante una lista fija en el builder. Por ejemplo, Human y Troll aparecen bajo Creature Subtypes, no como hijos directos de Type. Esto garantiza que seleccionar Human implique seleccionar Creature.

2. Mana Cost

No utilizaremos un grupo alternative: los componentes del coste no son excluyentes. Una carta puede tener simultáneamente mana genérico, blanco y azul. Además, Generic Mana y Colorless Mana son dimensiones distintas.

Los componentes se generan a partir de Phase 2. Así podremos incorporar símbolos híbridos, pirexianos y otros componentes cuando el extractor los represente adecuadamente, sin tener que rediseñar el template.

3. Colores

Colors, Color Identity y Color Indicator son tres propiedades independientes. No debemos inferir una a partir de otra ni imponer equivalencias entre ellas. Sus cardinalidades se ajustarán a las observaciones.

4. Power/Toughness

El grupo es opcional, pero, cuando aparece, ambas propiedades son obligatorias. Los valores numéricos se acotan mediante los límites observados y los valores especiales se representan como alternativas independientes con su atributo value.
